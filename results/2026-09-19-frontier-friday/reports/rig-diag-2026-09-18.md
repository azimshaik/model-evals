## Findings needing action

1. **Unclean shutdown at ~21:24 today.** `last` records the previous GUI session as `crash`; boot -1's
   journal stops mid-stream at 21:24:08 with no shutdown sequence, next boot at 21:39 reports the user
   journal "corrupted or uncleanly shut down". No kernel panic/Oops/MCE was logged before the cut, and
   there is no kdump/pstore, so the cause is unproven — sudden power loss/hard hang is the likely class.
   Watch for a repeat; a 4× 2080 Ti transient on one PSU is the thing to suspect if it recurs under load.
2. **GPU2 = 09:00.0 is the outlier.** It carries the most heat (83 °C at 250 W, fan 100 %) and had
   **242 s of SW power capping** since driver load versus 0 s on GPU3. It is almost certainly the
   TP4 straggler. Capping all cards helps it most; consider re-seating/repasting it or giving it the
   best airflow slot if it stays the hot one.
3. **`nvidia-persistenced.service` failed at this boot** (daemon started before `/dev/nvidia*` existed).
   Persistence mode was enabled manually (`nvidia-smi -pm 1`, daemon-based, non-persistent across reboot).
   With the vLLM service holding all four GPUs this is cosmetic, but the unit will keep failing at boot.
4. **Board fan/rail sensors are not exposed.** `nct6775` finds the NCT6791/6796D but the BIOS ACPI
   claims the region (`SystemIO 0x295-0x296 conflicts with OpRegion \_GPE.HWM`), so no `hwmon` node →
   no case-fan RPM and no 12 V/5 V/3.3 V rails from lm-sensors. Fix requires
   `acpi_enforce_resources=lax` on the kernel cmdline; verify before committing.

## Re-running

```bash
sudo ~/inference/rig-diag.sh                 # snapshot battery
sudo ~/inference/rig-diag.sh --load          # + 3×1000-token sustained decode with telemetry
sudo ~/inference/rig-diag.sh --caps 175 150  # + power-limit sweep (leaves the last cap applied)
```

Run the whole script under `sudo`: a `sudo` *inside* a script does not receive Hermes' piped password,
so privileged sections silently no-op otherwise. Power limits are **not** persistent across reboot and
there is currently no unit re-applying them.
